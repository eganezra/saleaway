# Story 2.3: Visibility, Staleness and Override Rules

## Status

Ready for Review

## Story

**As a** bargain hunter,
**I want** only current sales shown,
**so that** I don't click through to ended sales.

## Acceptance Criteria

1. Stores flagged hidden are not shown.
2. A store is not shown when it was last validated more than 72 hours ago (FR10, FR15, NFR3). A store that has never been validated is measured from the time it was added, and an active override counts as a fresh check. Without this, the site would be empty until the first pipeline run (Epic 3).
3. Records marked ended are not shown.
4. Override precedence is built here, so every later story can rely on it: an active override's percentage replaces the extracted one, its hide flag hides the store, its sale URL replaces the stored one, and an expired override is ignored (FR12).
5. A unit test covers each rule, including a never-validated store and an expired override.

### The rules (`packages/core/src/visibility.ts`)

Both functions are **pure**. The architecture names `isVisible`; the SM adds `resolveStore`, which returns what the page needs, so the web app does not apply the rules twice. Everything after "Input" is the SM's decision on top of the rules in `architecture/core-workflows.md` (a record is hidden when it is `ended`, when its freshness time is older than 72 hours, or when an active override hides it; the freshness time is the latest of `last_validated_at`, the creation time of an active override, and, only for a store that has never been validated, the creation time of the retailer row; **PO ruling 2026-10-30: any active override counts, as AC2 and FR10 say, not only one that sets a percentage**).

```typescript
export interface VisibilityRecord {            // one sale_records row, or null when there is none
  state: 'active' | 'ended' | 'unknown';
  discountPercent: number | null;
  lastValidatedAt: string | null;              // ISO 8601 UTC
}
export interface VisibilityOverride {          // one overrides row, or null when there is none
  discountPercent: number | null;
  hide: boolean;
  saleUrl: string | null;
  expiresAt: string | null;
  createdAt: string;
}
export interface StoreInput {
  isVisible: boolean;                          // retailers.is_visible
  saleUrl: string | null;                      // retailers.sale_url
  createdAt: string;                           // retailers.created_at
  record: VisibilityRecord | null;
  override: VisibilityOverride | null;
}
export type HiddenBecause = 'flag' | 'no_sale_url' | 'override_hide' | 'ended' | 'stale';
export interface StoreView {
  visible: boolean;
  hiddenBecause: HiddenBecause | null;         // null when visible
  discountPercent: number | null;              // the override's percentage, else the record's, else null ("On sale")
  saleUrl: string | null;                      // the override's URL, else the retailer's
  freshAt: string | null;                      // the freshness time used (ISO 8601 UTC), for later stories
}
export function resolveStore(input: StoreInput, now: Date): StoreView;
export function isVisible(input: StoreInput, now: Date): boolean;   // resolveStore(input, now).visible
```

Rules, applied in this order; the first that hides the store gives `hiddenBecause`:

1. **Active override.** An override is *active* when it exists and its `expiresAt` is null or later than `now` (an `expiresAt` equal to `now` is expired). An `expiresAt` that is not a valid date is treated as **not expired** (the operator's intent stays; the override command validates dates, so this is a defensive choice, and it is tested). An expired override is ignored in every rule below (AC4). An override is never changed or deleted by these functions.
2. **`flag`:** `isVisible` is false. (An override cannot show a store that the operator flag hides: showing a store is `is_visible`.)
3. **`no_sale_url`:** the effective sale URL does not start with `https://`. The effective URL is the active override's `saleUrl` when it is set, else the retailer's `saleUrl`. This is the same safety rule the page already applies to every `href`.
4. **`override_hide`:** an active override has `hide` true.
5. **`ended`:** the record's `state` is `ended`, **unless an active override sets a percentage** (`discountPercent` not null): the operator then says the store is on sale and the override wins. *[SM decision, flagged for the PO: the PRD says overrides win over extracted values but does not say whether they also beat `ended`.]*
6. **`stale`:** the freshness time is older than 72 hours. Freshness time = the latest of: (a) the record's `lastValidatedAt` **or, when there is none (never validated, or no record at all), the retailer's `createdAt`**; and (b) the active override's `createdAt` (AC2, "an active override counts as a fresh check"; any active override, whatever it sets: the operator has looked at the store). **Exactly 72 hours old is still shown**; one second more is hidden. A timestamp that is not a valid date is treated as missing; if no usable freshness time remains, the store is `stale` (fail closed).

`discountPercent` in the view is the active override's percentage when it sets one (AC4), else the record's percentage, else `null`. `saleUrl` in the view is the effective URL above (AC4). `freshAt` is the freshness time (ISO 8601 UTC) or null. `STALE_AFTER_HOURS = 72` is a named constant in the file, exported. **Do not read the clock, the database or the network in this file.** [Source: architecture/core-workflows.md#state-rules-per-fetch-result; prd/requirements.md#fr10, #fr12, #fr15, #nfr3; architecture/data-models.md#saleRecord, #override; architecture/coding-standards.md#critical-fullstack-rules]

### The home page query (`apps/web/src/lib/db.ts`)

One query, one round trip. The visibility rules are applied in code (core), not in SQL, except that stores hidden by the operator flag are not read at all:

```sql
SELECT r.slug, r.name, r.sale_url, r.created_at,
       s.state AS record_state, s.discount_percent AS record_percent, s.last_validated_at,
       o.discount_percent AS override_percent, o.hide AS override_hide, o.sale_url AS override_url,
       o.expires_at AS override_expires_at, o.created_at AS override_created_at
FROM retailers r
JOIN categories c ON c.id = r.category_id
LEFT JOIN sale_records s ON s.retailer_id = r.id
LEFT JOIN overrides o ON o.retailer_id = r.id
WHERE r.is_visible = 1
ORDER BY c.sort_order, r.rank, r.id
```

- **The `sale_url LIKE 'https://%'` condition leaves the SQL**: a store whose own URL is missing can be shown by an override URL, so core decides (rule 3). The page still never puts a non-https URL in an `href`; keep the existing second-line defence in `getVisibleStores`.
- `getVisibleStores(db, now: Date)` maps each row to a `StoreInput` (`override_hide` 0 or 1 becomes a boolean; a row with no `record_state` has `record: null`; a row with no `override_created_at` has `override: null`), calls `resolveStore`, and returns `{ slug, name, saleUrl, discountPercent }` for the visible ones, **in the query's order** (ranking by discount is Stories 2.1 and 2.2). `now` comes from `loadHomeViewModel(db, log, now = new Date())`; the page passes nothing, so tests can pass a fixed time.
- `loadHomeViewModel` keeps its behaviour: `ok`, `empty` (healthy database, nothing to show) or `error` (the database failed, logged once as `home_failed`). When rule 6 hides every store the page is `empty`, which shows "Sales are loading, check back soon."

### Testing

- **Framework:** Vitest 5.0.5. Core tests are plain unit tests; web tests use the stub database of `home-view-model.test.ts`. No test touches a real database or the network. `pnpm test` must run core, ops, web and pipeline.
- **`packages/core/tests/visibility.test.ts`** (a fixed `now`, a small builder for `StoreInput`): one test per rule and per boundary.
  - **Flag (AC1):** `isVisible` false is hidden (`flag`), even with an override that sets a percentage.
  - **Staleness (AC2):** validated 1 hour ago is visible; **exactly 72 hours ago is visible; 72 hours and 1 second ago is `stale`**; a never-validated store (record with `lastValidatedAt` null, and also no record at all) is measured from `createdAt`: created 71 hours ago visible, created 73 hours ago `stale`; a store created 73 hours ago with a record validated 1 hour ago is visible (the record wins, `createdAt` is not used); an active override created 1 hour ago makes a store that was last validated 5 days ago visible (`freshAt` is the override's `createdAt`), whether it sets a percentage or only a `saleUrl`; an **expired** override does not refresh it; an override with only `hide` hides the store (it is not shown, whatever it refreshes).
  - **Ended (AC3):** `ended` is hidden (`ended`); `unknown` and `active` are not; an `ended` record with an active override that sets a percentage is visible; with an **expired** one it is hidden.
  - **Overrides (AC4):** the active override's percentage replaces the record's (and the record's percentage is used when the override has none, and `null` when neither has one); `hide` hides (`override_hide`); an **expired** override (expiry in the past, and exactly `now`) is ignored for percentage, hide and URL; an override with no expiry is active; an **invalid** `expiresAt` keeps it active; the override's `saleUrl` replaces the retailer's, and an `http://`, `javascript:` or empty override URL or retailer URL is `no_sale_url`; a store with no retailer URL but an active override URL is visible and uses the override URL; an expired override URL falls back to the retailer's.
  - **Order of reasons:** a store that is both flagged hidden and stale reports `flag`; `no_sale_url` before `override_hide` before `ended` before `stale`.
  - **Bad data (fail closed):** an unparsable `createdAt` with no usable `lastValidatedAt` is `stale`; an unparsable `lastValidatedAt` falls back to `createdAt`.
  - **Purity:** the input objects are not changed; the same input and `now` always give the same view; `isVisible` equals `resolveStore(...).visible`.
- **`apps/web/tests/home-view-model.test.ts`:** the query text contains `r.is_visible = 1`, `LEFT JOIN sale_records`, `LEFT JOIN overrides` and `ORDER BY c.sort_order, r.rank`, and **no longer** contains `sale_url LIKE`; `getVisibleStores` with rows: a stale row is dropped, an ended row is dropped, an override hide row is dropped, an override URL replaces the stored one in the result, an override percentage appears as `discountPercent`, `override_hide` 0 and 1 map correctly, a row with no record and a recent `created_at` is kept, **a non-https URL never reaches the result** (the existing test, kept); the order of the rows is the query's order; `loadHomeViewModel` returns `empty` when every row is hidden by the rules and `error` (one `home_failed` log) when the database fails; both take a fixed `now`.
