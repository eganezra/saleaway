### The coverage command (`scripts/ops/src/coverage-plan.ts`, `coverage.ts`)

`pnpm ops:coverage --local | --remote [--run <id>] [--out <file>]` (no default for the database: exactly one of the two; `--run` defaults to the latest run that has at least one result; `--out` defaults to printing to the screen, and a file is written only when `--out` is given; the path, **resolved from the repository root**, must be inside `docs/data/` and end in `.md`: `docs/data/../README.md` and an absolute path are refused). It **only reads** (`queryRows`, read-only SELECTs, values checked: the run id is an integer). Add `"ops:coverage"` to the root `package.json`.

- **`coverage-plan.ts`** (pure, no I/O): takes the rows the command read, the hidden list (`docs/data/hidden-stores.json`) and the run's facts, and returns the report data and the Markdown. Its inputs are plain arrays so a test passes fixtures.
- **The rows to read** (three read-only queries): the run (`pipeline_runs`: id, trigger, `started_at`, `finished_at`, `stores_total`) with its first and last result times; for **every retailer** `slug`, `name`, category name, `extraction_method`, `is_visible`, `seed_status`, `sale_url IS NULL`, the run's result (`run_results` of that run: `result`, `http_status`, `discount_percent`, `duration_ms`, `error`, or none), its `sale_records` row (`state`, `validation`, `discount_percent`, `last_result`, `last_validated_at`) and whether an active override exists.
- **The buckets** (each visible store is in exactly one; the counts add up to the visible stores; a test checks it): **with a percentage** (a record `active` with a `discount_percent`), **"On sale" only** (`active` with no percentage: split into `validation` `content_verified` without a figure and `url_verified`, and by the run's result `js_only` or `ok`), **ended** (`state = ended`), **blocked** (the run's result `blocked`), **not found** (`not_found`), **redirected away** (`redirected_away`), **errors** (`error`), **never checked** (`unknown`, or no result), **manual** (`skipped_manual`: with or without an override). Then the **hidden** stores (`is_visible = 0`), split by the reason of the hidden list (and "no sale page" for a store with no sale address and not on the list). Also: how many stores got a result, `stores_total`, the run's duration (first to last result).
- **Stores that need manual handling** (a table with the store, the bucket and a **plain reason**: the HTTP status or error text for blocked and error, "manual method, no override yet" for a manual store without an override, "never checked: <last result>" for `unknown`, "judged ended: check the page by hand" for `ended`, "no figure found" for a valid page with no percentage): every store in the buckets blocked, not found, redirected, errors, never checked, ended and manual, and every valid store with no figure. Sorted by bucket then slug.
- **The records are the latest night's, not the run's.** `run_results` keeps one night's result, figure and status, but **`sale_records` (state, validation, figure) is overwritten by every run**, so the "ended", "On sale only" and "never checked" buckets show the records as they are when the command runs. The command must say so: the report states "sale records as of <the newest `last_checked_at`>", and **when any record is newer than the run's last result it adds a warning line at the top** ("These records were written after this run: the state buckets show a later night"). A test covers both cases. For run 17 this means the report must be made **before 03:00 UTC on 2026-11-01**; a read-only snapshot of the joined rows as they stood on 2026-10-31 at 08:00 UTC (106 stores, 57 with a run-17 result, newest record 03:14:39) is kept at `/private/tmp/claude-501/-Users-egan-saleaway/94168619-3b56-4747-a7a3-12ca4a67591e/scratchpad/run17-snapshot.json` as evidence if the deadline is missed (it holds slugs, names, methods, results and states, no page text; never commit it).
- **The Markdown** has these parts, in order: a title and a line with the run (id, trigger, start, how long it took, results saved), the date it was made and the "sale records as of" line; **the summary table** (bucket and count, with the total visible and the number hidden); **stores that need manual handling**; **stores with no percentage** (the "On sale" only list, with the method and the result); **hidden stores** (by reason, each with its slug); and a closing line "Made by `pnpm ops:coverage`; it reads the database only." **Only slugs, names, numbers and short reason words: no page text and no URL query.**
- **Tests** (`scripts/ops/tests/coverage-plan.test.ts`, `args.test.ts` for the new arguments): the buckets add up for a mixed fixture of about 20 stores covering every bucket; a store is in exactly one bucket; the split of "On sale" only; the hidden split by reason and the "no sale page" case; the manual-handling reasons; a run with no results (an empty report, no crash); the Markdown has the six parts in order and the totals match the table; **the output holds no `http`, no `?` and no HTML** (a hostile store name with `<script>` and `|` is escaped, a pipe in a name does not break the table); the arguments (neither or both of `--local` and `--remote` is an error, `--run abc` and `--run -1` are errors, `--out` outside `docs/data/`, with `..` that leaves it, absolute, or not ending in `.md` is an error); the command refuses to write a file when the query failed (it does not write a partial file).
- Not built here: a standing report for every night (`ops:health`, Story 4.2), a fix-up of any data from the report.
