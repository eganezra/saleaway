# Story 2.1: Store Row Design

## Status

Done

## Story

**As a** bargain hunter,
**I want** each store row to show how deep the discount is and how fresh it is,
**so that** I can decide which sale to visit.

## Acceptance Criteria

1. A store row shows the store name, a bold "Up to X% off" when a percentage is known, or "On sale" when not (FR13).
2. A row shows "Checked today" or "Checked N days ago" (FR15), or "Not checked yet" when the store has never been checked.
3. Rows and cards are text-only. No retailer images, logos or product content (NFR7).
4. Rows meet WCAG AA contrast, are keyboard-focusable, and have a clear tap target of at least 44px (NFR9).
5. Layout is a single column on small phones and a grid on larger screens.

### The time of the last check (`packages/core/src/visibility.ts`)

FR15 says "each row shows when the sale was last checked". `freshAt` also holds the added-at fallback and the override's "now", so add one field to `StoreView`:

```typescript
/** When the store was last really checked: the active override's moment (now), else the record's
 *  `lastValidatedAt`, else null (never checked, even though it may still be shown for 72 hours after it was added). */
checkedAt: string | null;
```

- Active override → `toIsoUtc(now)` (the operator vouches for the store, as in Story 4.1: the row says "Checked today").
- Else a record whose `lastValidatedAt` parses as a date → that time as `toIsoUtc`.
- Else `null`. An unparsable `lastValidatedAt` is `null`.
- **Nothing else changes**: the visibility rules, `freshAt` and the order of reasons are exactly as in Story 2.3. A hidden store still gets a `checkedAt`.

[Source: packages/core/src/visibility.ts; prd/requirements.md#fr15]

### The row's data (`apps/web/src/lib/storeRow.ts`)

```typescript
export type PillTier = 'hot' | 'warm' | 'plain';
export interface StoreRowData {
  slug: string; name: string; saleUrl: string;
  percent: number | null;      // only a whole number from 1 to 99, else null
  tier: PillTier;              // 'hot' 50 or more, 'warm' 1 to 49, 'plain' (no figure)
  checkedText: string;         // 'Checked today' | 'Checked 1 day ago' | 'Checked 3 days ago' | 'Not checked yet'
  checkedAge: 'today' | 'older' | 'never';
  label: string;               // the link's accessible name
}
export function toRowData(store: StoreLink, now: Date): StoreRowData;
```

- **`percent`**: `store.discountPercent` when it is an integer from 1 to 99 (the widest value either source can hold: the override's range; name the two limits in constants with that comment), else `null`. Anything else (a stray 0, 100, -5, 12.5, NaN) is shown as "On sale", never as a figure.
- **Days since the last check:** `Math.floor((now - checkedAt) / 24 hours)`, never below 0 (a time in the future counts as today). **`0` days → "Checked today"** (the last check was less than 24 hours ago), `1` → "Checked 1 day ago", `n` → "Checked n days ago" (at most 3 on the live site). A missing or unparsable `checkedAt` → "Not checked yet" (`checkedAge: 'never'`). Rolling 24 hour periods are used, not South African calendar days: the nightly run is at 05:00 South African time, and calendar days would label every row "1 day ago" between midnight and the run. [Source: architecture/coding-standards.md ("Time is UTC ISO 8601... convert to South African time only in the UI"); front-end-spec.md ("stale (older than 24 hours)")]
- **`label`** (the link's accessible name, set as `aria-label`): `"<name>, up to 50% off, checked today, opens in a new tab"`; with no figure `"<name>, on sale, checked today, opens in a new tab"`; with no check `"<name>, on sale, not checked yet, opens in a new tab"`. It always contains the visible text (WCAG 2.5.3, label in name). [Source: front-end-spec.md#store-row]

### The row's design (`DiscountPill.astro`, `StoreRow.astro`)

Follow `docs/front-end-spec.md` (Store Row, Discount Pill, Color Palette, Accessibility). Text only (NFR7).

- **Anatomy, left to right:** the store name (semibold, wraps onto a second line, **never** cut with an ellipsis, `overflow-wrap: anywhere`, the visited tint on the name only), under it the small "Checked" line, then on the right the **discount pill**, then a chevron. **No rank number** in this story: the rank only means something inside a category card (Story 2.2).
- **The whole row is one link** (`<a>`, `target="_blank"`, `rel="noopener noreferrer"`, `data-store`, `aria-label={label}`). The pill and the "Checked" line are not separate links. The chevron is `aria-hidden`.
- **`DiscountPill.astro`** (props: `percent`, `tier`): "Up to" in smaller type (13px) and the figure bold, for example "Up to **50% off**"; the number is always in the text, so colour is never the only signal. `hot`: pink fill (`--color-pink`), ink text, 2px solid ink border. `warm`: yellow fill (`--color-yellow`), ink text, 2px solid ink border. `plain`: white fill, ink text, **2px dashed** ink border, the text "On sale". The pill never wraps inside itself (`white-space: nowrap`) and does not shrink (`flex: none`).
- **The "Checked" line** (13px, never smaller): `today` → mint background (`--color-mint`) with ink text; `older` → yellow background (`--color-yellow`) with ink text (the spec's warning treatment: the words "Checked 2 days ago" carry the meaning, the colour only helps); `never` → no background, subtle text. Pink is never used for text and never as the only boundary.
- **Tokens to add** to `tokens.css`: `--color-subtle: #6B6B6B` (rank numbers, chevrons and the "Not checked yet" text: 5.3:1 on white, 4.9:1 on the cream page). Use only the tokens; no hard-coded colour in a component.
- **Contrast (the spec's calculated ratios):** ink on white 18.9:1; ink on yellow 13.1:1; ink on mint 13.1:1; ink on pink 6.1:1; subtle on white 5.3:1; muted (`#4A4A4A`) on white 8.9:1. The 3px ink border supplies the 3:1 boundary of the row.
- **Tap target and keyboard:** the row keeps `min-height: 44px` (more in practice), the `:focus-visible` outline stays, rows are in an `<ol role="list">` with at least 8px between them (the existing 16px gap), and the pressed state (`:active`) moves the shadow like the hover state; **hover effects only on devices that can hover** (`@media (hover: hover)`). No transition or animation, so nothing needs `prefers-reduced-motion`.
- **Layout (AC5):** the grid has **1 column below 640px, 2 from 640px, 3 from 1024px, 4 from 1440px** (the spec's breakpoints), content capped at 1280px as it is. Write it with explicit `grid-template-columns` and `min-width` media queries in `index.astro`'s style. Story 2.2 moves this grid to the category cards and makes the rows a single-column list inside each card.
- **Typography:** the system font stack stays. The spec proposes a heading font (Space Grotesk, an open assumption); **do not add a web font here** (a new dependency and a performance cost for NFR2). The pill uses the body font in bold.
- **`index.astro`** passes the row data (`<StoreRow row={row} />`) instead of three props. The h1, intro line, `EmptyState` and 503 behaviour do not change.

### Gaps and decisions for the developer to note

1. **`checkedAt` is new** and honest: the row never says "Checked today" for a store that was only added today and never validated (it says "Not checked yet"). The override case does say "Checked today" (Story 4.1: an override counts as a fresh check). **PO confirmed 2026-10-30:** the honest answer is better than a false "today", and a store whose first nightly check fails will show "Not checked yet" until the 72 hour rule hides it. The PRD's criterion 2 now says so.
2. **Rolling 24 hour periods**, not calendar days, for "today" (reason above). **PO confirmed 2026-10-30.**
3. **The percentage range is 1 to 99 (PO confirmed 2026-10-30; verified in `db/migrations/0001_init.sql`: `sale_records` 5 to 90, `overrides` 1 to 99).** Anything else is "On sale".
4. **The "stale" variant** of the spec (older than 24 hours) is the yellow "Checked N days ago" line; the row itself does not change shape.
5. **No heading font, no rank number, no category colours** in this story (see the bullets above): they belong to Story 2.2 or are open design decisions.
6. **`aria-label` on the link** replaces the link's content for screen readers; it is built from the same words as the visible text so they never differ. Story 2.4's axe run is the automated check; this story's check is manual.
7. **Caching:** the page is rendered per request today, so "today" is exact. When Story 2.4 caches the page, the cache lifetime must stay short enough that "Checked today" stays true (note for 2.4).

### Refactoring Performed

- **File**: `apps/web/src/components/StoreRow.astro`
  - **Change**: `.store` gets `flex-wrap: wrap` and `.text` gets `flex: 1 1 7rem` (was `flex: 1`).
  - **Why**: the pill never shrinks (`flex: none`, `nowrap`) and the name column could shrink to nothing, so on a 320 px phone **and at about 640 to 680 px, where two columns are only about 290 px wide each**, the name column got about 80 px: "Superbalist" broke mid-word as "Superbalis / t" and the "Checked today" label wrapped onto two lines. That is the single-column and grid range of criterion 5, so it is not an edge case.
  - **How**: the name keeps at least 7rem; when the row is too narrow for that, the pill and chevron drop to their own line instead of squeezing the name into broken words. At 360 px and above (and in the 3 and 4 column layouts) nothing changes. Checked again at 320, 360 and 640 px: the names are whole, the pill sits under the "Checked" line. The architecture doc (shard and `architecture.md`, identical) says so in one clause.
