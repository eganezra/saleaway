# Story 2.2: Category Sections

## Status

Ready for Review

## Story

**As a** bargain hunter,
**I want** stores grouped by category,
**so that** I can jump to the type of shop I care about.

## Acceptance Criteria

1. The home page shows one section per category (marketplaces, fashion, sport, tech, home, DIY, beauty and health, grocery and liquor, baby, kids and toys, pets) (FR14).
2. Within a section, stores are ordered by biggest known discount first, then "On sale" stores by rank, with ties broken by rank (FR14). Before extraction exists (Epic 3), every store is "On sale", so the order falls back to rank.
3. A simple anchor menu at the top jumps to each section.
4. Categories with no visible stores are not shown.

### The ordering rule (`packages/core/src/rank.ts`)

FR14: within a category, **the biggest known discount first**; stores with only "On sale" (no percentage) follow, **ordered by store rank**; **ties are broken by store rank**. The architecture names `rankStores` in `packages/core/src/rank.ts` and `rank.test.ts`. [Source: prd/requirements.md#fr14; architecture/unified-project-structure.md; architecture/components.md]

```typescript
export interface Rankable { percent: number | null; rank: number }
/** A new array: known percentages first (largest first), then the others; within each group and for equal
 *  percentages, the lower `rank` first; equal ranks keep the order they came in. Does not change its input. */
export function rankStores<T extends Rankable>(items: readonly T[]): T[];
```

A `rank` that is not a finite number sorts after every real rank (the column is NOT NULL, default 999, so this only guards bad data). The sort is stable.

### The view model (`apps/web/src/lib/categories.ts`, `homeViewModel.ts`)

```typescript
export const ROWS_SHOWN = 8; // the card shows 8 rows, then "Show all N"
export interface CategoryData {
  slug: string; name: string; tagline: string; colorToken: string;
  count: number;                 // the stores in it (all visible stores are on sale)
  rows: StoreRowData[];          // all rows, ordered (FR14); each has `position` 1..count
}
export function buildCategories(stores: StoreLink[], now: Date): CategoryData[];
```

- Group by `category.slug`, **keeping the order in which the categories first appear** (the query is already ordered by `c.sort_order`), so a category that has no visible store never appears (AC4).
- Within a category: `toRowData(store, now)` for each store, then `rankStores` on `{ ...row, rank: store.rank }` (rank by the row's `percent`, the figure the row shows), then `position` = place in the ordered list starting at 1. `StoreRowData` gains `position: number` (set by `buildCategories`; `toRowData` itself does not know it: give it a default or make the builder add it, as you find cleaner, and keep `toRowData`'s existing tests passing).
- **The cut at 8 is the component's job**, using `ROWS_SHOWN`: the view model gives all rows.
- `HomeViewModel`: `{ kind: 'ok'; categories: CategoryData[] } | { kind: 'empty' } | { kind: 'error' }`. `loadHomeViewModel` builds it with the same `now` it passes to `getVisibleStores`. `empty` is still "no visible store at all".

### The design

Follow `docs/front-end-spec.md` (Category Card, Category Chip, Store Row, Accessibility, Responsiveness, Spacing). Text only (NFR7).

- **Page structure** (`index.astro`): the h1 and intro as now; `<CategoryChips>`; then one `<section id="<category slug>" aria-labelledby="<slug>-title">` per category inside the card grid. **One `<h1>`, one `<h2>` per category, no skipped levels.**
- **`CategoryChips.astro`** (props: the categories' slug and name): `<nav aria-label="Categories">` with a list of links `href="#<slug>"`, each a pill with a 2px ink border and the category name, **at least 44px tall**, 8px or more between them, a visible focus outline (the global one). Default, hover (hover devices only) and focus-visible states. **Below 640px the row scrolls horizontally and is sticky at the top of the screen** (`position: sticky; top: 0`, page-colour background, above the cards); from 640px it wraps onto more lines and is not sticky. **A sticky row must not hide what the visitor jumps to or tabs to** (WCAG 2.2 "Focus Not Obscured", the spec's target): below 640px set `scroll-padding-top` on `html` to the chip row's height (so an anchor jump and a keyboard focus both scroll clear of it); from 640px it is 0. Check it: Tab down the page below 640px and see that the focused row is never under the chips.
- **`CategoryCard.astro`** (props: a `CategoryData`): a white card with a 3px ink border, a hard 6px ink shadow and 20px padding. The header: a small coloured tab on its left edge (`var(--cat-default)` for every category today; use `var(--<colorToken>)` with `--cat-default` as the fallback so a later category colour is a CSS-only change), the **h2** with the name, a **black square count badge** with a white numeral (the visible number only, plus visually hidden text "N stores on sale"; `aria-hidden` on the numeral), and the tagline in **italic inside quotes** (typographic quotes added with CSS or text; the tagline text itself is not changed). Then an `<ol role="list">` of the first `ROWS_SHOWN` rows. **When there are more than 8 stores**, a native `<details>` follows (no JavaScript): `<summary>` reads "Show all N" (N = the count) while closed and "Show fewer" while open (two spans switched with CSS on `details[open]`), is a **real tap target of at least 44px**, has the focus outline and a chevron that turns; inside it a second `<ol role="list" start="9">` with the rest. **A card with 8 or fewer never shows the control.** Every row is in the HTML whether the control is open or not.
- **`StoreRow.astro`, inside a card:** one link row as in Story 2.1 (the same data, the pill, the "Checked" line, the chevron, the accessible name, the 7rem wrap rule) with these changes: **the rank number** `position` at the left, in `--color-subtle` (muted grey, `aria-hidden`: the list already numbers the rows); **no own border or shadow**, but a 2px ink line between rows (none after the last); **at least 48px tall** and the whole row tappable; hover (hover devices only) the background becomes `--color-page` (the cream), and the pressed state adds the same background and an underline on the name; **no yellow, mint or pink background on a row**: the grey rank number is only 3.7:1 on yellow and on mint, and it is 4.9:1 on the cream; the visited tint on the name stays. The row's `aria-label` does not change.
- **Layout of the cards:** a CSS grid of **1 column below 640px, 2 from 640px, 3 from 1024px, 4 from 1440px**, `align-items: start` (a card is as tall as its rows; cards in a row do not stretch), 16px gap, content capped at 1280px as now. **It is a plain grid, not a masonry**: the spec allows "CSS grid or columns masonry", and a grid keeps the reading and tab order the same as the order in the page.
- **Tokens:** add `--cat-default` to `tokens.css` (the sky blue `#7cc4ff`, the spec's decorative accent, 10.1:1 with ink text; it is only a decorative tab, never text). Use only tokens; no hard-coded colour in a component.

No heading font, no web font.

### Gaps and decisions for the developer to note

1. **A plain grid, not a masonry** (reason above). **PO confirmed 2026-10-30.**
2. **Chips use the full category names** ("Sport, athleisure & outdoor"): the spec's short chip names ("Sport", "Tech") would need a new column or a data change; the row scrolls on a phone and wraps from 640px. **PO confirmed 2026-10-30**; short names are a later data change if the wrapped row looks heavy in the browser check.
3. **Every category has the same tab colour** (`cat-default`) because the seed gives all ten the same token; per-category colours are a later data change in `db/seed/categories.json` plus a token each, with no code change here.
4. **The active-chip highlight is not built** (it needs a script file; no story has built one yet). The chips have default, hover and focus states.
5. **The rank number is the row's place in its card** (1, 2, 3 ...), not `retailers.rank`.
6. **Sticky chips only below 640px**, as the spec says; there is no header yet for them to sit under, so they stick to the top of the screen.
7. **The page is still rendered per request**, so "Checked today" is exact; when Story 2.4 caches the page, the cache lifetime must stay short (note carried from Story 2.1).
8. **Row look changes** (flat rows in a card, a rank number, 48px): the data, label, pill and "Checked" logic of Story 2.1 do not.
