# Story 2.5: Ad Slots, Analytics and Legal Pages

## Status

Approved

## Story

**As the** operator,
**I want** ad slots, simple analytics and legal pages,
**so that** the site is ready to earn and to be trusted.

## Acceptance Criteria

1. The layout includes clearly marked ad slots (top, between categories, footer) that render nothing until switched on by a configuration flag (FR18).
2. Cookie-free analytics counts visits and click-outs per store (FR19, NFR8). The Web Analytics part is confirmed after the domain is connected (Story 4.4).
3. About / How it works and Privacy pages exist (FR20). The About page has a short "Our bot" part: what the bot is, that it reads each store's sale page about once a day and that it obeys robots.txt. There is no Contact page and no retailer removal route (decided 2026-10-30); `/contact` forwards to that part of the About page, because the bot's user-agent carries that address.
4. A footer links to both pages.
5. The layout does not shift when ad slots turn on (no large layout jump).

### Click-outs (`db/migrations/0003_click_counts.sql`, `lib/click.ts`, `lib/db.ts`, `pages/api/click.ts`)

FR19: click-outs per store, counters only, **no personal data**. [Source: architecture/data-models.md#clickcount; architecture/api-specification.md; architecture/database-schema.md]

- **Migration** `0003_click_counts.sql`: exactly the architecture's table: `click_counts (day TEXT NOT NULL, retailer_id INTEGER NOT NULL REFERENCES retailers(id), clicks INTEGER NOT NULL DEFAULT 0, PRIMARY KEY (day, retailer_id))`. Additive only.
- **`lib/db.ts` `recordClick(db, slug, day, amount)`** (the SQL lives here, nowhere else in the web app): one statement, `INSERT INTO click_counts (day, retailer_id, clicks) SELECT ?, id, ? FROM retailers WHERE slug = ? ON CONFLICT (day, retailer_id) DO UPDATE SET clicks = clicks + excluded.clicks`, bound parameters; it returns whether a row was changed (`meta.changes` 0 means the slug is unknown). One row written per click.
- **`lib/click.ts`** (pure, with injected randomness): `parseSlug(body)` (trimmed, at most 100 characters, `^[a-z0-9-]+$`, else null); `parseSampleRate(value)` (a number above 0 and at most 1, else 1); `shouldCount(rate, random)` (`random() < rate`); `clickAmount(rate)` = `Math.round(1 / rate)` so a sampled count stays an estimate of the true total; `utcDay(now)` = `YYYY-MM-DD`.
- **`POST /api/click`**: put the logic in **`src/lib/clickHandler.ts`**, a function `handleClick(request, deps)` that takes everything it needs as arguments (`db`, the logger, `random`, `now`, the sample rate setting) and returns a `Response`, so it is unit-tested without Astro and without `cloudflare:workers`; **`src/pages/api/click.ts`** only wires `env.DB`, the shared `log`, `Math.random`, `new Date()` and `env.CLICK_SAMPLE_RATE` and exports `POST` (and `ALL` for the 405). The body is the slug as plain text (what `navigator.sendBeacon` sends). In order: (1) a request body over **100 bytes** (by `Content-Length` when present, and read at most 128 bytes) is a **413**; (2) an `Origin` header that is present and is not this site's origin is a **403** (a missing one is allowed); (3) a slug that does not parse is a **400**; (4) sampling: with probability `1 - rate` answer **204 without writing**; (5) `recordClick` with `clickAmount(rate)` for today's UTC day; an unknown store is a **404**; (6) success is **204** with no body. **Every response has `Cache-Control: no-store`.** A database failure is logged once with the structured logger (`click_failed`, `slug` and the error text, **nothing about the visitor**) and answered **503**; it never throws. Any other method on the path is a **405** with `Allow: POST`. **Nothing about the visitor is read, logged or stored**: no IP address, no user-agent, no cookie, no referrer.
- **`CLICK_SAMPLE_RATE`** is a `wrangler.jsonc` var, `"1"` by default (every click counted). **Risk to note in the docs (do not build more here):** each counted click writes one D1 row and the Free plan allows 100,000 row writes a day for the whole database (the pipeline writes about 120 a night); an automated flood of `POST /api/click` could use that up and make the database refuse writes. The sampling switch lowers the rate by hand; **a Cloudflare rate-limiting rule on `/api/click` (a dashboard setting, needs the real domain) belongs to the launch checklist** (see "Gaps"). The home page still **reads** when writes are refused (D1 refuses writes first), but say what you find in "Local check".

### Visits and the script (`scripts/site.ts`, `lib/analytics.ts`, `BaseLayout.astro`)

- **`src/scripts/site.ts`** (the click beacon): on `click` and `auxclick` (a middle click opens a new tab) on `document`, find `event.target.closest('a[data-store]')`; if found, `navigator.sendBeacon('/api/click', link.dataset.store)` inside `try`/`catch` (a failure is ignored; the link still works). No other behaviour, no `localStorage`, no cookie, under 1 KB. **One small file, same origin.**
- **It must not be inlined.** Astro can inline a small script into the page, which the CSP (`script-src 'self'`, no `'unsafe-inline'`) would block. After `pnpm build`, check the built page: **no `<script>` without a `src`**, and the script has a hashed `/_astro/…js` address. If Astro inlines it, set `vite.build.assetsInlineLimit` to `0` in `astro.config.mjs` (or emit the file in a way that keeps it external) and say what you did. The smoke test checks it.
- **Cloudflare Web Analytics** (visits, cookie-free): `lib/analytics.ts` has `analyticsToken(value)`: the token only if it matches `^[A-Za-z0-9]{16,64}$`, else null. When `CF_WEB_ANALYTICS_TOKEN` (a `wrangler.jsonc` var, **empty by default**) gives a token, the layout adds, at the end of `<body>`: `<script defer src="https://static.cloudflareinsights.com/beacon.min.js" data-cf-beacon='{"token":"<token>"}'></script>` (the JSON built with `JSON.stringify`, so it cannot break out of the attribute). No token: **no tag at all**. The CSP already allows that host for scripts and `cloudflareinsights.com` for connections. **Do not set a real token** and do not load the script in your checks (it needs the real domain: Story 4.4 confirms it). ### Ad slots (`AdSlot.astro`, `lib/ads.ts`)

FR18 and the spec's Ad Slot: always labelled "Advertisement", a thin dashed frame so it cannot be mistaken for a store row, **reserves its size**, never inside a category card's list. [Source: front-end-spec.md#ad-slot; prd/requirements.md#fr18]

- **The flag:** `ADS_ENABLED`, a `wrangler.jsonc` var, `"false"` by default; `lib/ads.ts` has `isAdsEnabled(value)` (true only for the exact text `"true"`, like `ALLOW_INDEXING`). **Off: the slot renders nothing at all and keeps no space** (no wrapper element, no margin).
- **On:** `<aside data-ad-slot="top|grid|footer" aria-label="Advertisement">` with a small-caps label "Advertisement" (13px at least), a 2px **dashed** ink border, and an inner area that **reserves its size with `min-height`** (`aspect-ratio` or fixed): `top` 90px (shown from 640px only: **no ad above the first card on a phone**), `grid` 250px (a 300x250 rectangle), `footer` 90px from 640px and 60px below. The inner area is **empty** (no ad network is chosen: its own snippet goes there after approval, together with its hosts in the CSP, a separate small change). Nothing outside the frame moves when it is switched on or off.
- **Placements:** `top` after the chip row and before the grid of cards; `grid` as **one grid item after the third category card** (a card-sized grid cell; it is never inside a card's list); `footer` at the top of the footer, above the links. All three come from one flag.
- **No layout shift (AC5):** the reserved heights above are fixed in CSS, so turning the flag on adds space but moves nothing that is already on screen after it loads (the slots are in the server-rendered HTML, not injected later). Show it in "Local check" with a Lighthouse run of a build with the flag on: cumulative layout shift 0.

### Technology and constraints

TypeScript 5.9.3, Astro 7.4.4 with `@astrojs/cloudflare` 14.4.3, Vitest 5.0.5, Playwright 1.64.1. **No new dependency**, no pipeline change, no web font, no image, no cookie, no `localStorage`. One migration (additive). **Do not build ahead:** no ad network snippet, no real analytics token, no status strip, no sticker card, no consent banner, no per-visitor data, no search, no health report (Story 4.2 reads `click_counts`). **Free-tier note (coding standards):** this story adds **D1 writes per click** (one row per counted click, up to 100,000 a day for the whole database: see the risk above), no new reads on the home page, and the new pages add no D1 read; `CLICK_SAMPLE_RATE` is the lever. [Source: architecture/coding-standards.md#critical-fullstack-rules; architecture/tech-stack.md]

### Gaps and decisions for the developer to note

1. **The header, skip link and footer are built here** because no story builds them and the footer links (criterion 4) need a footer; the header lets a visitor on About or Privacy get home. **The status strip** ("N stores on sale today, updated today") **is in no story**: not built; **PO ruled 2026-10-30: the status strip is not part of the MVP** (the freshness it would show is already on every row as "Checked ... ago"); it can come back in Epic 5. The front-end spec says so.
2. **No menu button** (two links fit on a 320px phone). **No Contact page** and no email: the plan change of 2026-10-30; `/contact` is a 302 so the bot's user-agent link works.
3. **The write-budget risk of `/api/click`** (above): the story ships the sampling switch only. **A Cloudflare rate-limiting rule on `/api/click` should be added to Story 4.5's launch checklist** (a dashboard setting on the real domain). **PO confirmed 2026-10-30; Story 4.5 now has a criterion 8 for it** (if the plan allows such a rule).
4. **Ad slots are empty frames when switched on** (no ad network yet); the flag stays `"false"` until an ad network approves the site. When it does, its snippet and hosts are a small follow-up change, and **the Privacy page and the cookie question (NFR8) are revisited first**.
5. **The analytics tag appears only with a token** (empty by default); Story 4.4 sets the token on the real domain and confirms visits are counted.
6. **The Privacy page names no operator and no email** (not decided). It says only what is true today. **PO ruled 2026-10-30: it does not name an operator for now**; the question comes back with the ad-network step, when POPIA obligations are revisited (NFR8).
7. **About and Privacy are cached like the home page** (10 minutes at the edge, revalidated by the browser), keyed by build.
8. **The migration is not applied to the live database here.** The web deploy does it first (README).
9. **Bots can inflate click counts**; the numbers are an approximation (no cookie, no visitor identity), good enough for a per-store ranking.

### Project Structure Notes

The layout matches the architecture's tree (`Header.astro`, `Footer.astro`, `AdSlot.astro`, `scripts/site.ts`, `api/click.ts`, `about.astro`, `privacy.astro`). `contact.ts` replaces the tree's `contact.astro` (a redirect, by the plan change). `lib/click.ts`, `lib/ads.ts` and `lib/analytics.ts` are small pure files kept apart so they can be unit-tested without Astro. No conflict.

### Testing

- **Framework:** Vitest 5.0.5 for the unit tests (no network, no real database: a fake `D1Database` records the SQL and parameters); Playwright for the smoke test. `pnpm test` runs core, ops, web and pipeline and not the smoke test.
- **`tests/click.test.ts`:** `parseSlug` accepts `takealot`, `a-b-1`, trims whitespace and rejects empty, 101 characters, upper case, spaces, `;`, `'`, `/`, `<script>` and non-text; `parseSampleRate` gives the number for `"1"`, `"0.5"`, `"0.01"` and 1 for `""`, `"0"`, `"-1"`, `"2"`, `"abc"`, `undefined`; `shouldCount` is true when `random()` is below the rate and false at or above it (boundaries); `clickAmount(1)` is 1, `0.5` is 2, `0.1` is 10, `0.3` is 3; `utcDay` for `2026-10-31T23:59:59Z` and `2026-11-01T00:00:00Z`.
- **`tests/db.test.ts` (new):** `recordClick` runs **one** prepared statement with bound parameters (no value in the SQL text), binds the day, the amount and the slug in the order the SQL uses them, returns true when `meta.changes` is 1 and false when 0, and passes a database error up.
- **`tests/analytics.test.ts`:** `analyticsToken` accepts a 32-character token, trims, and rejects `""`, `undefined`, `bad token!`, a token with a quote, `<`, a space, one under 16 and one over 64 characters.
- **`tests/ads.test.ts`:** `isAdsEnabled` is true only for `"true"`.
- **`tests/clickHandler.test.ts`** (fake database, fake logger, fixed `random` and `now`): 204 and one `recordClick` call with today's UTC day and the amount; **413** for a body over 100 bytes (by `Content-Length` and by an unannounced long body); **403** for a foreign `Origin`, and a missing or same-origin `Origin` is allowed; **400** for a bad slug or an empty body; **404** when the database says the store is unknown; **204 without a write** when `random()` is at or above the rate, and **the amount is 2 at rate 0.5**; **503** and one `click_failed` log line when the database throws, and the log line holds the slug and the error text and **no header, address or user-agent of the request**; every answer has `Cache-Control: no-store`; no answer has a `Set-Cookie`; the handler never throws.
- **`tests/smoke.spec.ts`:** the checks listed in "The smoke test".
