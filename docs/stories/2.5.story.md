## Story

## Acceptance Criteria

1. The layout includes clearly marked ad slots (top, between categories, footer) that render nothing until switched on by a configuration flag (FR18).
2. Cookie-free analytics counts visits and click-outs per store (FR19, NFR8). The Web Analytics part is confirmed after the domain is connected (Story 4.4).
3. About / How it works and Privacy pages exist (FR20). The About page has a short "Our bot" part: what the bot is, that it reads each store's sale page about once a day and that it obeys robots.txt. There is no Contact page and no retailer removal route (decided 2026-10-30); `/contact` forwards to that part of the About page, because the bot's user-agent carries that address.
4. A footer links to both pages.
5. The layout does not shift when ad slots turn on (no large layout jump).

### Click-outs (`db/migrations/0003_click_counts.sql`, `lib/click.ts`, `lib/db.ts`, `pages/api/click.ts`)

FR19: click-outs per store, counters only, **no personal data**. [Source: architecture/data-models.md#clickcount; architecture/api-specification.md; architecture/database-schema.md]

- **Migration** `0003_click_counts.sql`: exactly the architecture's table: `click_counts (day TEXT NOT NULL, retailer_id INTEGER NOT NULL REFERENCES retailers(id), clicks INTEGER NOT NULL DEFAULT 0, PRIMARY KEY (day, retailer_id))`. Additive only.
- **`lib/db.ts` `recordClick(db, slug, day, amount)`** (the SQL lives here, nowhere else in the web app): one statement, `INSERT INTO click_counts (day, retailer_id, clicks) SELECT ?, id, ? FROM retailers WHERE slug = ? ON CONFLICT (day, retailer_id) DO UPDATE SET clicks = clicks + excluded.clicks`, bound parameters; it returns whether a row was changed (`meta.changes` 0 means the slug is unknown). One row written per click.
- **`lib/click.ts`** (pure, with injected randomness): `parseSlug(body)` (trimmed, at most 100 characters, `^[a-z0-9-]+$`, else null); `parseSampleRate(value)` (a number above 0 and at most 1, else 1); `shouldCount(rate, random)` (`random() < rate`); `clickAmount(rate)` = `Math.round(1 / rate)` so a sampled count stays an estimate of the true total; `utcDay(now)` = `YYYY-MM-DD`.
- **`POST /api/click`**: put the logic in **`src/lib/clickHandler.ts`**, a function `handleClick(request, deps)` that takes everything it needs as arguments (`db`, the logger, `random`, `now`, the sample rate setting) and returns a `Response`, so it is unit-tested without Astro and without `cloudflare:workers`; **`src/pages/api/click.ts`** only wires `env.DB`, the shared `log`, `Math.random`, `new Date()` and `env.CLICK_SAMPLE_RATE` and exports `POST` (and `ALL` for the 405). The body is the slug as plain text (what `navigator.sendBeacon` sends). In order: (1) a request body over **100 bytes** (by `Content-Length` when present, and read at most 128 bytes) is a **413**; (2) an `Origin` header that is present and is not this site's origin is a **403** (a missing one is allowed); (3) a slug that does not parse is a **400**; (4) sampling: with probability `1 - rate` answer **204 without writing**; (5) `recordClick` with `clickAmount(rate)` for today's UTC day; an unknown store is a **404**; (6) success is **204** with no body. **Every response has `Cache-Control: no-store`.** A database failure is logged once with the structured logger (`click_failed`, `slug` and the error text, **nothing about the visitor**) and answered **503**; it never throws. Any other method on the path is a **405** with `Allow: POST`. **Nothing about the visitor is read, logged or stored**: no IP address, no user-agent, no cookie, no referrer.
- **`CLICK_SAMPLE_RATE`** is a `wrangler.jsonc` var, `"1"` by default (every click counted). **Risk to note in the docs (do not build more here):** each counted click writes one D1 row and the Free plan allows 100,000 row writes a day for the whole database (the pipeline writes about 120 a night); an automated flood of `POST /api/click` could use that up and make the database refuse writes. The sampling switch lowers the rate by hand; **a Cloudflare rate-limiting rule on `/api/click` (a dashboard setting, needs the real domain) belongs to the launch checklist** (see "Gaps"). The home page still **reads** when writes are refused (D1 refuses writes first), but say what you find in "Local check".

### Visits and the script (`scripts/site.ts`, `lib/analytics.ts`, `BaseLayout.astro`)

- **`src/scripts/site.ts`** (the click beacon): on `click` and `auxclick` (a middle click opens a new tab) on `document`, find `event.target.closest('a[data-store]')`; if found, `navigator.sendBeacon('/api/click', link.dataset.store)` inside `try`/`catch` (a failure is ignored; the link still works). No other behaviour, no `localStorage`, no cookie, under 1 KB. **One small file, same origin.**
- **It must not be inlined.** Astro can inline a small script into the page, which the CSP (`script-src 'self'`, no `'unsafe-inline'`) would block. After `pnpm build`, check the built page: **no `<script>` without a `src`**, and the script has a hashed `/_astro/…js` address. If Astro inlines it, set `vite.build.assetsInlineLimit` to `0` in `astro.config.mjs` (or emit the file in a way that keeps it external) and say what you did. The smoke test checks it.
- **Cloudflare Web Analytics** (visits, cookie-free): `lib/analytics.ts` has `analyticsToken(value)`: the token only if it matches `^[A-Za-z0-9]{16,64}$`, else null. When `CF_WEB_ANALYTICS_TOKEN` (a `wrangler.jsonc` var, **empty by default**) gives a token, the layout adds, at the end of `<body>`: `<script defer src="https://static.cloudflareinsights.com/beacon.min.js" data-cf-beacon='{"token":"<token>"}'></script>` (the JSON built with `JSON.stringify`, so it cannot break out of the attribute). No token: **no tag at all**. The CSP already allows that host for scripts and `cloudflareinsights.com` for connections. **Do not set a real token** and do not load the script in your checks (it needs the real domain: Story 4.4 confirms it). ### Ad slots (`AdSlot.astro`, `lib/ads.ts`)

FR18 and the spec's Ad Slot: always labelled "Advertisement", a thin dashed frame so it cannot be mistaken for a store row, **reserves its size**, never inside a category card's list. [Source: front-end-spec.md#ad-slot; prd/requirements.md#fr18]

- **The flag:** `ADS_ENABLED`, a `wrangler.jsonc` var, `"false"` by default; `lib/ads.ts` has `isAdsEnabled(value)` (true only for the exact text `"true"`, like `ALLOW_INDEXING`). **Off: the slot renders nothing at all and keeps no space** (no wrapper element, no margin).
- **On:** `<aside data-ad-slot="top|grid|footer" aria-label="Advertisement">` with a small-caps label "Advertisement" (13px at least), a 2px **dashed** ink border, and an inner area that **reserves its size with `min-height`** (`aspect-ratio` or fixed): `top` 90px (shown from 640px only: **no ad above the first card on a phone**), `grid` 250px (a 300x250 rectangle), `footer` 90px from 640px and 60px below. Nothing outside the frame moves when it is switched on or off.

- **No layout shift (AC5):** the reserved heights above are fixed in CSS, so turning the flag on adds space but moves nothing that is already on screen after it loads (the slots are in the server-rendered HTML, not injected later).
