1. D1 migrations create tables for categories, retailers, sale records, overrides, pipeline runs and run results (FR1, FR9, FR11, FR12), and the 10 categories are seeded. The click counts table arrives later with Story 2.5.

3. After seeding, the table holds all 106 spreadsheet stores (plus Crocs SA once its URL is found). The 92 with primary sale URLs are visible, and the 14 without (12 with no sale page, 2 with only a Black Friday page) are hidden (FR2). Stores listed in several categories get unique slugs, and non-numeric ranks ("Alt") are mapped to numbers (see `docs/architecture.md`, "Seed data rules").
4. Adding a store is documented as inserting one row (FR3).
5. Migrations can run locally and in production.

### Migration 0001

Write this as `db/migrations/0001_init.sql`. It is the schema in the architecture, minus `click_counts`, with ISO timestamp defaults (decision 1). It was run against SQLite by the SM and parses and enforces its constraints.

```sql
-- db/migrations/0001_init.sql
CREATE TABLE categories (
  id          INTEGER PRIMARY KEY,
  slug        TEXT NOT NULL UNIQUE,
  name        TEXT NOT NULL,
  tagline     TEXT NOT NULL DEFAULT '',
  sort_order  INTEGER NOT NULL DEFAULT 0,
  color_token TEXT NOT NULL DEFAULT 'cat-default'
);

CREATE TABLE retailers (
  id                     INTEGER PRIMARY KEY,
  slug                   TEXT NOT NULL UNIQUE,
  name                   TEXT NOT NULL,
  homepage_url           TEXT NOT NULL,
  category_id            INTEGER NOT NULL REFERENCES categories(id),
  rank                   INTEGER NOT NULL DEFAULT 999,
  platform               TEXT,
  sale_url               TEXT,
  black_friday_url       TEXT,
  black_friday_verified  INTEGER NOT NULL DEFAULT 0 CHECK (black_friday_verified IN (0,1)),
  extraction_method      TEXT NOT NULL DEFAULT 'html'
    CHECK (extraction_method IN ('shopify_json','html','structured_data','manual')),
  seed_status            TEXT NOT NULL DEFAULT 'search_only'
    CHECK (seed_status IN ('verified_products','verified_js_shell','search_only','no_sale_page')),
  is_visible             INTEGER NOT NULL DEFAULT 1 CHECK (is_visible IN (0,1)),
  created_at             TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now')),
  updated_at             TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE INDEX idx_retailers_category_rank ON retailers(category_id, rank);

CREATE TABLE sale_records (
  retailer_id       INTEGER PRIMARY KEY REFERENCES retailers(id),
  state             TEXT NOT NULL DEFAULT 'unknown' CHECK (state IN ('active','ended','unknown')),
  validation        TEXT NOT NULL DEFAULT 'none'
    CHECK (validation IN ('content_verified','url_verified','none')),
  discount_percent  INTEGER CHECK (discount_percent BETWEEN 5 AND 90),
  last_result       TEXT,
  first_seen_at     TEXT,
  last_checked_at   TEXT,
  last_validated_at TEXT,
  ended_at          TEXT
);

CREATE TABLE overrides (
  retailer_id      INTEGER PRIMARY KEY REFERENCES retailers(id),
  discount_percent INTEGER CHECK (discount_percent BETWEEN 1 AND 99),
  hide             INTEGER NOT NULL DEFAULT 0 CHECK (hide IN (0,1)),
  sale_url         TEXT,
  expires_at       TEXT,
  note             TEXT NOT NULL DEFAULT '',
  created_at       TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);

CREATE TABLE pipeline_runs (
  id            INTEGER PRIMARY KEY,
  started_at    TEXT NOT NULL,
  finished_at   TEXT,
  trigger       TEXT NOT NULL CHECK (trigger IN ('cron','manual')),
  stores_total  INTEGER NOT NULL DEFAULT 0,
  stores_ok     INTEGER NOT NULL DEFAULT 0,
  stores_failed INTEGER NOT NULL DEFAULT 0
);

CREATE TABLE run_results (
  id               INTEGER PRIMARY KEY,
  run_id           INTEGER NOT NULL REFERENCES pipeline_runs(id),
  retailer_id      INTEGER NOT NULL REFERENCES retailers(id),
  result           TEXT NOT NULL,
  http_status      INTEGER,
  discount_percent INTEGER,
  duration_ms      INTEGER,
  error            TEXT,
  created_at       TEXT NOT NULL DEFAULT (strftime('%Y-%m-%dT%H:%M:%SZ','now'))
);
CREATE INDEX idx_run_results_run ON run_results(run_id);
CREATE INDEX idx_run_results_retailer_time ON run_results(retailer_id, created_at);
```

Notes: `discount_percent BETWEEN 5 AND 90` is the sanity range from Story 3.4 (a value outside it is stored as `NULL`, meaning "On sale"). D1 allows 100 bound parameters per query. Write volumes are far below the 100,000 rows-written-a-day Free limit. The home page (Story 1.4 onward) joins `retailers`, `categories`, `sale_records` and `overrides` in one query. **Migrations are additive only** (new tables and columns), so rolling code back never needs a database rollback. ### Seed rules

The seed file is `docs/data/retailers-seed.tsv`: UTF-8, tab-separated, **106 data rows plus one header row**, no quote characters, no blank lines, one category per row. Columns used (match by header name; the status column header is `Status (28 Oct 2026)`, so match any header that **starts with** `Status`): `Category`, `Rank`, `Store`, `Homepage`, `Primary sale / promo URL`, `Secondary / Black Friday URL`, `Platform / URL pattern`, `Status…`. The columns `Label used on site` and `How it was found` are **not** used. Missing values in the file are written as a dash `—` (with explanatory text after it, for example `— (not found)`).

| Column in `retailers` | Rule |
|---|---|
| `slug` | `slugify(Store)`: lowercase, delete apostrophes (`'` and `’`), replace every run of other non-alphanumeric characters with one `-`, trim `-` at both ends. If the slug is already used by an **earlier row**, use `<store-slug>-<category-slug>`. If that is also taken, **fail with an error** naming the row. |
| `name` | The `Store` cell exactly as written (for example `Game (Massmart)`, `Checkers / Sixty60`). |
| `homepage_url` | `Homepage`, must start with `https://`. |
| `category_id` | The id of the category whose `name` equals `Category` (looked up by slug in SQL, never a hard-coded id). An unknown category is an error. |
| `rank` | `Rank` if it is an integer (1 to 10). If it is `Alt`: `100 + <the row's 1-based position among the rows of its category>`. Example: `Side Step` is the 11th Sport row, so rank 111. |
| `platform` | The `Platform / URL pattern` cell, trimmed, **unchanged** (for example `Shopify /collections/`). `NULL` if empty or it starts with `—`. |
| `sale_url` | `Primary sale / promo URL` if it starts with `https://`, otherwise `NULL` (this covers every `— …` value). |
| `black_friday_url` | `Secondary / Black Friday URL` if it starts with `https://`, otherwise `NULL`. (`SHEIN SA` has `— (Black Friday banner, no link yet)`, so it is `NULL`.) |
| `black_friday_verified` | Not set by the seed (stays the default `0`). |
| `seed_status` | From the status cell, by prefix: `Verified – products visible` gives `verified_products`; `Verified – page loads (products load via JS)` gives `verified_js_shell`; `Found via search – not fetched` gives `search_only`; `No sale page / not found` gives `no_sale_page`. The dash in the file is an en dash (U+2013). Any other value is an error. |
| `extraction_method` | `manual` if the homepage host (without `www.`) is `amazon.co.za`, `game.co.za` or `checkers.co.za`; otherwise `shopify_json` if the `Platform / URL pattern` cell contains `Shopify` (any case); otherwise `html`. |
| `is_visible` | `1` if `sale_url` is not `NULL`, otherwise `0`. (The 12 `no_sale_page` rows **and** `Cielo` and `Builders`, whose status is `search_only` but have no primary URL.) |

**One row per listing:** five stores appear in two categories on purpose, each with its own URL: `Bash (TFG)`, `Superbalist`, `Ackermans`, `Hirsch's`, `Faithful to Nature`. Nine websites appear more than once overall. All of these stay as separate rows with unique slugs (the first keeps the plain slug, the later one gets the category suffix: `bash-tfg-fashion-apparel`, `superbalist-fashion-apparel`, `hirschs-home-decor-furniture`, `faithful-to-nature-grocery-liquor`, `ackermans-baby-kids-toys`). Counting a store once per website is done later, in the display rules (Story 3.7 and the status strip), not in the seed.

**Crocs SA is not in the spreadsheet.** FR2 adds it "once its sale URL is found" (the human check in Story 4.3). Do not add it here.

### Seed SQL

The seed command writes one SQL file and runs it with `wrangler d1 execute --file`. Use plain statements (no explicit transaction statements). Re-running is safe because every statement is an upsert on the unique `slug`:

```sql
INSERT INTO categories (slug, name, tagline, sort_order, color_token)
VALUES ('pets', 'Pets', 'Happy pets, happy wallet.', 10, 'cat-default')
ON CONFLICT(slug) DO UPDATE SET
  name = excluded.name, tagline = excluded.tagline,
  sort_order = excluded.sort_order, color_token = excluded.color_token;

INSERT INTO retailers (slug, name, homepage_url, category_id, rank, platform, sale_url,
                       black_friday_url, extraction_method, seed_status, is_visible)
VALUES ('hirschs', 'Hirsch''s', 'https://www.hirschs.co.za',
        (SELECT id FROM categories WHERE slug = 'home-decor-furniture'),
        6, NULL, 'https://…', NULL, 'html', 'search_only', 1)
ON CONFLICT(slug) DO UPDATE SET
  name = excluded.name, homepage_url = excluded.homepage_url, category_id = excluded.category_id,
  rank = excluded.rank, platform = excluded.platform, sale_url = excluded.sale_url,
  black_friday_url = excluded.black_friday_url, seed_status = excluded.seed_status,
  updated_at = strftime('%Y-%m-%dT%H:%M:%SZ','now');
```

- **Seed-owned columns** (updated on every run): `name`, `homepage_url`, `category_id`, `rank`, `platform`, `sale_url`, `black_friday_url`, `seed_status`, plus `updated_at`. **Never updated by the seed once the row exists:** `is_visible`, `extraction_method`, `black_friday_verified`, and everything in `sale_records` and `overrides`. They are only set when the row is first inserted. This is how the seed leaves an operator's hand edits alone (see decision 4).
- The seed writes **categories first, then retailers**, because of the foreign key.
- The categories are upserted on every column (the file `db/seed/categories.json` is their source of truth).
- Print a summary after a successful run (counts of categories and retailers, visible and hidden) through the logger.

### Validation before SQL

`wrangler d1 execute` takes a plain SQL string with no bound parameters, so **every value must be validated before it goes into SQL** and every text value must have its single quotes doubled (the names `Hirsch's` and `Food Lover's Market` need this). `buildSeed` (core) must reject, with an error that names the row:

- a `slug` that does not match `^[a-z0-9-]+$`, or an empty one;
- a URL (`homepage_url`, `sale_url`, `black_friday_url`) that does not start with `https://`, or contains a space, quote, backslash or control character;
- a `rank` that is not an integer from 1 to 999;
- an `extraction_method`, `seed_status` or `is_visible` outside the allowed values;
- any text with a control character (including a tab or newline inside a cell).

`sqlString` in the ops package doubles single quotes and also rejects control characters, as a second line of defence. Never use string concatenation of unvalidated file content in SQL. [Source: architecture/coding-standards.md#critical-fullstack-rules ("Safe SQL in the operator CLI")]

### Gaps and decisions for the developer to note

1. **Timestamp format conflict.** The architecture schema uses `DEFAULT (datetime('now'))`, which gives `2026-10-29 12:38:26` (no `T`, no `Z`), but the Coding Standards require `YYYY-MM-DDTHH:MM:SSZ`, and the visibility rule uses `retailers.created_at` as the "added" time for a never-validated store (FR10). This story follows the Coding Standards (`strftime`). Update the schema docs to match (Task 11).
2. **Category names and slugs.** The architecture gives `sport` as an example slug, but its only seed example is `ackermans-baby-kids-toys`, which implies the category slug is the full name slugified (`baby-kids-toys`). This story uses the spreadsheet names and `slugify(name)` for the slug. Category slugs become page anchors in Story 2.2, so a later change is possible but touches the page and any bookmarks.
3. **Where the code lives.** The seed transformation is pure and goes in `packages/core` (shared-logic rule), SQL building and the command go in `scripts/ops` (SQL only in ops scripts). `scripts/ops` becomes a workspace package for testing. `tsx` and `@types/node` (dev only, both approved) are the only new dependencies.
4. **"Never touches `is_visible` or `extraction_method` once an operator has changed them"** cannot be detected without an extra column. This story sets both only on first insert and never updates them on conflict. Consequence for Story 4.3: when a hidden store's sale URL is found later and re-seeded, `sale_url` is updated but the store **stays hidden** until the operator updates `is_visible`. That is by design.
5. **`black_friday_verified`** has no source in the spreadsheet, so it stays `0`. Story 2.6 (a stretch story) decides what to do with it.
6. **`platform` is stored as the spreadsheet text**, not normalised to `shopify`. The extraction method is derived from it at seed time. The data model's example `shopify` is only an example.
7. **Overlap with Story 4.1 (criterion 5).** The seed already sets Amazon.co.za, Game and Checkers to `manual`. Story 4.1 only has to confirm it.
8. **`color_token`** stays `cat-default` for all categories until Story 2.2 chooses the colours.
9. **No test framework for D1 yet.** Seed rules are covered by unit tests; the SQL and constraints are covered by the manual checks in Tasks 3, 7 and 9 (recorded in the Dev Agent Record). `@cloudflare/vitest-pool-workers` arrives with the first story that needs it.

### Refactoring Performed

Two defects found in `scripts/ops/src/seed.ts`, fixed and verified. These changes are **in the working tree and not committed**.

- **File**: `scripts/ops/src/seed.ts`
  - **Change**: the usage error and the new not-applied error use a field named `reason`, not `message`.
  - **Why**: the shared logger reserves `level`, `message` and `time` and silently drops fields with those names. So `pnpm ops:seed` with no flag printed only `{"level":"error","message":"seed_usage"}`, with the explanation missing, and the unit tests never saw it because they test the argument parser, not the printed line.
  - **How**: the line now reads `...,"reason":"Say which database to seed. Usage: pnpm ops:seed --local | --remote"`. Checked for no flag, both flags and an unknown flag.
- **File**: `scripts/ops/src/seed.ts`
  - **Change**: (1) the input is read and validated inside a `try/catch` that logs `seed_invalid` and returns 1, instead of letting an exception print a raw stack trace; (2) after Wrangler returns, the command asks the database whether the seeded rows are present (counts only the seeded slugs, quoted with `sqlString`) and logs `seed_not_applied` with exit code 1 if they are not, before it logs `seed_done`.
  - **Why**: I measured that when an operator answers "no" at Wrangler's prompt, **Wrangler exits with code 0**. The command would then have printed `seed_done` even though nothing was written. That is exactly the case the "no `--yes` for `--remote`" design invites.
  - **How**: verified (a) in the repository, local happy path: `seed_done`, exit 0; (b) a corrupted homepage in a scratch copy: `seed_invalid` with the line number, exit 1, no database call; (c) a simulated declined run (the scratch copy writes a no-op SQL file into an empty migrated database): `seed_not_applied` with expected 10 and 106 against found 0 and 0, exit 1. The production path uses the same code, but I did not re-run a live seed.
- **File**: `README.md`
  - **Change**: the `ops:seed` bullet now describes the prompt, the warning that the database may be unavailable while the file runs, and the `seed_not_applied` check.
  - **Why**: Wrangler's prompt text says the D1 database "will be unavailable to serve queries" during the run. That is harmless today (the run takes well under a second), but it matters once the site is live.
  - **How**: documentation only.
