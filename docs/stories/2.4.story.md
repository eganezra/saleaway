### The page cache (`src/lib/cache.ts`, `src/middleware.ts`, `index.astro`)

The architecture: the web Worker keeps the rendered home page HTML in the Cache API for about 10 minutes, which protects the D1 quotas and the 10 ms CPU limit and speeds up pages. [Source: architecture/tech-stack.md (Cache); architecture/security-and-performance.md#performance-optimization; architecture/core-workflows.md]

- **`cache.ts`** exports `PAGE_CACHE_SECONDS = 600` and one function that takes everything it needs (so a unit test passes fakes): the `Request`, a `next()` that renders the page, the cache object (`{ match(request), put(request, response) }`, the shape of `caches.default`) and a `waitUntil(promise)`.
  - It handles **only `GET`** requests; any other method goes straight to `next()`.
  - **The key is the page's address without its query string** (`new Request(origin + pathname)`), so `/?utm_source=x` and `/?a=1&b=2` share one entry and a visitor cannot make a new database query by changing the query string.
  - **Hit:** return the stored response with the header `x-cache: HIT` and render nothing.
  - **Miss:** call `next()`; **store the response only if** its status is 200 **and** its `Cache-Control` contains `public` (so a response that says `no-store` is never stored); store a **clone** with `waitUntil(cache.put(...))` (a failing `put` must never fail the request: catch it); return the original with `x-cache: MISS`. A response that is not stored is returned as it is, with `x-cache: BYPASS`.
  - **`match` or `put` throwing** is not an error for the visitor: the page is rendered and returned (`x-cache: BYPASS`).
- **Headers of a cached response may be immutable.** A `Response` from `cache.match` (or `fetch`) can have read-only headers in the Workers runtime: build the answer with `new Response(body, response)` (a copy) before setting `x-cache`. The unit test's fake cache cannot show this: the smoke test's second request (the real `HIT`) does, so it is the proof.
- **`middleware.ts`** (`defineMiddleware`): for the path `/` only, call `cache.ts` with `caches.default`, `context.locals.cfContext.waitUntil` (check the exact name in the installed `@astrojs/cloudflare` 14: Astro's Cloudflare `locals` carries the execution context) and `next`; every other path just calls `next()`. Keep it small: no logging per request.
- **`index.astro`** decides what may be cached: a `ok` page sets `Cache-Control: public, max-age=600` (use `PAGE_CACHE_SECONDS`); an `empty` page and an `error` page (503) set **`Cache-Control: no-store`**. The 503 may also send `Retry-After: 60`.
- **Not cached:** `/health`, `/robots.txt`, `/sitemap.xml` (they have their own `Cache-Control`, below) and anything but `/`.
- **A deploy does not empty the cache**: for up to 10 minutes after a deploy a visitor may still get the previous version's HTML. Say so in the docs.
- The page's **"Checked ... ago" words are right to within the cache lifetime** (10 minutes); that is accepted (Stories 2.1 and 2.2 carry the note).

### Search engine basics (`seo.ts`, `robots.txt.ts`, `sitemap.xml.ts`, `BaseLayout.astro`)

- **`wrangler.jsonc` `vars`** (web Worker): `SITE_URL` = `https://saleaway.online` (the decided domain; Story 4.4 attaches it) and `ALLOW_INDEXING` = `"false"`. Read them from `env` (the `Env` type is generated by `wrangler types`, which the `typecheck` script runs); never from globals. **Change the web app's `types` and `typecheck` scripts to `wrangler types --strict-vars=false`, as the pipeline's are**: by default Wrangler types a var as its literal value (`"false"`), and `env.ALLOW_INDEXING === 'true'` then fails the type check. [Source: architecture/coding-standards.md#critical-fullstack-rules]
- **`ALLOW_INDEXING` is the pre-launch brake** (carried from Story 1.4): while it is not exactly `"true"`, every page sends the header `X-Robots-Tag: noindex, nofollow`, the layout adds `<meta name="robots" content="noindex, nofollow">` and `robots.txt` says `User-agent: *` then `Disallow: /`. Switching it to `"true"` (Story 4.5, the launch checklist, by editing `wrangler.jsonc` and deploying) allows indexing. **Default is off**: the page on `workers.dev` must not be indexed before launch.
- **`seo.ts`** (pure functions, no I/O): `canonicalUrl(siteUrl, path)` (the site URL without a trailing slash plus the path; `/` gives `https://saleaway.online/`; an invalid or non-https site URL falls back to `https://saleaway.online`), `robotsTxt(siteUrl, allowIndexing)` (allowed: `User-agent: *`, `Allow: /` and a `Sitemap: <site>/sitemap.xml` line; not allowed: `User-agent: *`, `Disallow: /`) and `sitemapXml(siteUrl, paths)` (a valid `<urlset>` with one `<url><loc>` per path, XML-escaped; the paths are a fixed list in one place, today only `/`; Story 2.5 adds About, Privacy and Contact there).
- **`robots.txt.ts` and `sitemap.xml.ts`** are `GET` endpoints with `content-type: text/plain; charset=utf-8` and `application/xml; charset=utf-8` and `Cache-Control: public, max-age=3600`. The sitemap is served whether or not indexing is allowed.
- **`BaseLayout.astro`** gains props `title`, `description` and `path` (with defaults for the home page) and writes in `<head>`: `<title>` (home: "Saleaway: current sales from South African online stores", at most 60 characters), `<meta name="description">` (one sentence of at most 160 characters, plain facts: that it lists South African online stores with a sale on, with the biggest discount and when each was last checked, no superlatives), `<link rel="canonical">`, Open Graph `og:type` (`website`), `og:site_name`, `og:title`, `og:description`, `og:url`, `og:locale` (`en_ZA`), `twitter:card` (`summary`), the robots meta when indexing is off, and a favicon: a small **inline SVG data URI** `<link rel="icon" href="data:image/svg+xml,...">` (text-only: a simple shape or letter in the ink and yellow tokens' hex values; `img-src` allows `data:`). **No `og:image`** (no image is shipped; NFR7). `<html lang="en-ZA">`.
- **The default sale text in the description is a fact only**: do not state a store count or a time in a meta tag (it would be wrong in a cached copy).

### Security headers (`src/middleware.ts`)

The architecture names the headers; no story had set them. Set them on **every response in a production build** (`import.meta.env.PROD`; `astro dev` injects its own inline scripts and a websocket that the policy would block):

- `Content-Security-Policy: default-src 'self'; script-src 'self' https://static.cloudflareinsights.com; connect-src 'self' https://cloudflareinsights.com; style-src 'self' 'unsafe-inline'; img-src 'self' data:; frame-ancestors 'none'` (the architecture's text: Astro inlines scoped styles, so styles need `'unsafe-inline'`; scripts do not; the Cloudflare Insights host is for Story 2.5's analytics; ad network hosts are added when ads go live).
- `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`.
- Do **not** add HSTS here (it belongs to the real domain, Story 4.4) and do not remove a header Cloudflare sets.
- **Add them on the way out, to the response you return, and never store them in the cache.** If they were stored, a cached copy would keep the previous deploy's policy and its `X-Robots-Tag` for up to 10 minutes after a deploy (for example after `ALLOW_INDEXING` is switched on at launch). The `<meta name="robots">` inside the cached HTML is the one thing that can still be up to 10 minutes old after such a switch: say so in the docs.
- The CSP must not break the page: the smoke test fails on any console error or CSP violation.

[Source: architecture/security-and-performance.md#security-requirements; docs/stories/1.4.story.md (QA Results)]

### Testing
